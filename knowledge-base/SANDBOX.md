# The sandbox

Two layers, both Apple Seatbelt, both confined to one folder.

| | Layer 1 — the app | Layer 2 — the agents |
|---|---|---|
| What it confines | `Orca.app` and everything it spawns | each shell Orca (or Terminal) opens in the folder |
| Enforced by | `sandbox-exec` with a generated profile | `@anthropic-ai/sandbox-runtime` (`srt`), pinned **0.0.75** in `scripts/install-srt.sh` |
| Generated by | `scripts/sandbox/gen-orca-profile.sh` → `.claude-dev/state/orca.sb` | `scripts/sandbox/gen-settings.sh` → a per-launch settings file |
| Started by | `.claude-dev/bin/orca-launch` (the `Orca.app` bundle in the project root, or `./claude-dev open`) | `.claude-dev/bin/claude-orca-shell`, from the shell rc block |

Layer 2 runs *inside* layer 1, so nesting only ever tightens: a shell that
somehow escaped `srt` would still be inside the app's Seatbelt profile.

## Trust boundary

Everything is in the folder now — the template clone, `srt`, Claude Code,
`Orca.app`, the launcher. That is the whole point (no central install means
no unsandboxed copy to start by mistake) and it creates the one rule the
design turns on:

**Nothing that runs unsandboxed may be writable by anything sandboxed.**

`scripts/sandbox/host-owned-paths.sh` is the single list, sourced by *both*
generators, of paths inside the project that the host executes or trusts:

```
./claude-dev            the launcher stub in the project root
Orca.app                the double-clickable launcher bundle
.claude-dev/bin         launcher, wrapper, root finder, orca-launch
.claude-dev/template    this repo, cloned per project
.claude-dev/app         Orca.app itself, from the pinned DMG
.claude-dev/srt         the pinned sandbox-runtime install
.claude-dev/claude      the pinned Claude Code install
.claude-dev/state       generated profiles and settings the host feeds to
                        sandbox-exec and srt -- writable means escapable
.claude-dev/sandbox.json the folder's own knobs
orca.yaml               per-repo setup commands Orca runs unsandboxed
.worktreeinclude        consumed by Orca when it creates a worktree
.envrc                  sourced by direnv in unsandboxed shells
.beads/hooks            hook scripts bd runs
```

Both profiles deny writes to that list **last**, so nothing above can
re-open one. Reads stay allowed: the list is about authority, not secrecy.

`sandbox.json` is on it even though nothing executes it, because what it
*contains* — `orca.profileExceptions`, `filesystem.extraAllowWrite`,
`network.extraAllowedDomains` — widens a layer at the next launch. An agent
that could edit it could hand itself the real home one launch later. You
edit it from outside the sandbox, which is where the authority to widen a
sandbox belongs.

## `run/` versus `state/`

Two directories under `.claude-dev`, and the difference matters:

- **`state/`** is host-written and **write-denied to both layers**:
  `orca.sb`, `orca.sha256`, the launch log. It carries authority.
- **`run/`** is the one directory under `.claude-dev` the sandbox itself
  writes: `tier.json`, `selftest.json`, `config-hash`, the `srt-debug-*.log`
  captures. It carries results. Nothing in it is host-executed, so nothing
  in it needs denying.

A third, `.claude-dev/{home,tmp}`, is the sandbox's `HOME` and `TMPDIR`.

## Where each launch's `srt` settings file goes

Not in `state/` (write-denied to layer 1, and the wrapper runs there, so the
launch would fail on the write), and not in `run/` or `.claude-dev/tmp`
(writable to layer 1 — but also to layer 2, and that file is what *defines*
layer 2). It goes in a private per-launch directory under the per-user temp
tree, `mktemp -d "$TMPDIR/claude-orca.XXXXXX"`, created fresh for each
shell and never reachable from inside the sandbox it configures.

## How every shell ends up inside

The marker block in `~/.zshrc`, `~/.zprofile` and `~/.bash_profile` is
generic: it walks up from `$PWD` looking for `.claude-dev/bin/claude-orca-shell`
and execs it. That wrapper asks `claude-orca-root` whether the cwd belongs to
a registered project (`git rev-parse --git-common-dir` → primary checkout →
does it have `.claude-dev/sandbox.json`? non-git folders walk up), generates
the settings and runs `srt --settings <generated> -c 'exec zsh -l'`.

Orca spawns your **login shell** per terminal, so this happens before Orca
types `claude --dangerously-skip-permissions` — and equally for Codex,
Gemini, OpenCode, `orca terminal create --command …`, and a plain Terminal
window opened in the folder.

**Fail closed.** If `srt` or `sandbox-exec` are missing, or the wrapper
errors, the shellrc shadows `claude`, `codex`, `gemini` and `opencode` with
functions that refuse and print why. There is no unsandboxed fallback, at
either layer: no `sandbox-exec`, no profile or no app bundle means
`orca-launch` does not launch.

## Layer 2 scope

`allowWrite`, derived per session:

- **Primary checkout**: `<project>`, `<project>/.claude-dev/home`,
  `<project>/.claude-dev/tmp`.
- **Linked worktree**: `<worktree>`, plus the primary's `.git`, `.beads`,
  `.claude-dev/home`, `.claude-dev/tmp`, `.claude-dev/run` — and nothing
  else. Sibling worktrees are explicitly not writable (there is a probe).

`denyRead: [<real home>]`; `allowRead` adds back `<project>`, `<worktree>`,
`~/.local/bin`, `~/.local/share/claude`, `~/.orca/agent-hooks` (and the Orca
runtime dir only in CLI mode). `~/.ssh`, `~/.aws` and Documents are
unreadable by construction, not by a rule someone remembered to write.

Network: `strictAllowlist: true` over the defaults — `api.anthropic.com`,
`claude.ai`, `console.anthropic.com`, `platform.claude.com`,
`statsig.anthropic.com`, `*.sentry.io`, `github.com`, `api.github.com`,
`*.githubusercontent.com`, `registry.npmjs.org`, `pypi.org`,
`files.pythonhosted.org`, `cdn.playwright.dev`,
`playwright.download.prss.microsoft.com` (the last two so `take-screenshot
url` can fetch its headless browser) — union `network.extraAllowedDomains`.
Also `allowLocalBinding: true` (dev servers, the beads database server,
Orca's hook endpoint on `127.0.0.1:$ORCA_AGENT_HOOK_PORT`), `allowPty:
true`, `enableWeakerNetworkIsolation: true` (one `trustd` mach-lookup,
needed for Go TLS in `gh`, `bd` and `dolt`), `allowAppleEvents: false`, and
`allowUnixSockets: []` — except in Orca CLI mode, where it carries the same
Orca runtime dir `allowRead` gets, because the socket and a readable path to
it are one decision.

## Environment inside

```
HOME                  <primary>/.claude-dev/home
CLAUDE_CONFIG_DIR     $HOME/.claude
TMPDIR                <primary>/.claude-dev/tmp
GIT_CONFIG_GLOBAL     $HOME/.gitconfig
GH_CONFIG_DIR         $HOME/.config/gh
BEADS_DIR             <primary>/.beads
ORCA_USER_DATA_PATH   <real home>/Library/Application Support/orca
CLAUDE_ORCA_SANDBOXED 1
CLAUDE_ORCA_REAL_HOME <real home>
CLAUDE_ORCA_ROOT      <primary>
DISABLE_AUTOUPDATER   1
PATH                  <primary>/.claude-dev/bin:<primary>/.claude-dev/template/bin:/opt/homebrew/bin:…
```

The folder's own `bin/` **leads** the PATH, so the `claude` an agent here
resolves is this folder's pinned copy and never one installed elsewhere. The
sandbox `HOME` carries our own `.zshrc`, so the environment inside is the
template's, never your dotfiles.

## The self-test

Seventeen probes, run by `scripts/sandbox/selftest.sh` inside the sandbox.
Registration runs them and **refuses to hand off to Orca** unless they pass;
`claude-dev --doctor` re-runs them and prints the table with a one-line
reason each. `--dry-run` lists the probes without executing any.

| # | Probe | Expectation |
|---|---|---|
| 1 | `write-outside-denied` | `touch` under the real home fails |
| 2 | `read-real-home-denied` | `ls <real home>/.ssh` (or the home) fails |
| 3 | `keychain-denied` | `security find-generic-password -s 'Claude Code-credentials'` fails |
| 4 | `project-writable` | a temp file under the project can be created and removed |
| 5 | `worktree-writable` | same, in the current worktree |
| 6 | `sibling-worktree-denied` | another worktree is not writable |
| 7 | `tmp-outside-denied` | `touch` under `/private/tmp` fails |
| 8 | `network-blocked-domain` | `curl https://example.com` fails |
| 9 | `network-allowed-domain` | `curl https://api.anthropic.com/` returns any HTTP status |
| 10 | `orca-socket-unreachable` | `orca status --json` fails unless `orca.cli` is true |
| 11 | `sandbox-exec-present` | `sandbox-exec` on PATH (Darwin; reports `bwrap` elsewhere) |
| 12 | `srt-version-pinned` | installed `srt` version equals the `SRT_VERSION` pin |
| 13 | `git-hooks-audit` | git hooks reference only paths covered by `denyWrite` |
| 14 | `orca-profile-active` | layer 1 is really on: a write outside the folder fails |
| 15 | `home-redirected` | `HOME` resolves inside `.claude-dev/home` |
| 16 | `orca-data-in-folder` | Orca's user data landed in the folder, not the real home |
| 17 | `host-files-write-denied` | the host-owned list above is unwritable |

Probes 14–17 are **layer-1 probes**: they can only be judged from a terminal
this folder's Orca opened, and report N/A (never PASS) anywhere else —
`CLAUDE_ORCA_LAYER=orca` is what says so. A probe returns 0 (expected), 1
(violated) or 2 (could not run); the runner exits 0 only when none failed.

## Reading the generated profiles

**Layer 1** — `.claude-dev/state/orca.sb`, regenerated on every launch, is
plain SBPL and meant to be read. It is **last-match-wins**, so read it
bottom-up: a rule can only be qualified by one beneath it. The order is
`(allow default)` for the mediated-service surface, then the filesystem
denials under `/Users` and `/Volumes`, the metadata allowances for every
ancestor of the folder, `deny write /`, the folder itself, the temp and
`/dev` allowances, your `orca.profileExceptions`, and finally the
host-owned deny block. The Keychain mach services are denied by name near
the bottom, after every filesystem rule, unless `orca.keychain` is true.

**Layer 2** — `claude-orca-shell` runs the self-test with `SRT_DEBUG=true`
and captures `srt`'s stderr, which is the Seatbelt profile *it* generated,
to `<primary>/.claude-dev/run/srt-debug-<sha1(worktree)>.log`.

Read those two files when a denial surprises you: they are the policy the
kernel enforced, not a description of it.

## bash 3.2

macOS ships bash **3.2.57**, and the wrapper runs before anything newer is on
PATH. Every script here must run under it: no associative arrays, no `${x^^}`,
no `mapfile`, and in particular no `+=` onto an empty array under `set -u`
(the one real incompatibility this port hit). `scripts/lint-bash32.sh` and a
real 3.2 build in the test suite enforce it — see `tests/helpers/ensure_bash32`.

## Known limits

- `sandbox-exec` is deprecated-but-shipped; Claude Code's own sandbox uses it,
  so it is the supported path in practice.
- Apple Events stay denied, so OAuth flows print a URL to paste rather than
  opening a browser.
- `.git/config` stays write-denied inside because Orca runs git *unsandboxed*
  in the same repository; remotes are set by you or by bootstrap, never by
  the agent.
