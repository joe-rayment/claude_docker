Brief: https://claude.ai/code/artifact/7ea155b9-6575-470e-b551-62d4f480f2a6 . Epic claude-orca-8a0. Slice A first (its stall detection runs the rest); B and C in parallel in separate Orca worktrees after A merges.

## Slice A (claude-orca-8a0.1)
Slice A -- dispatch reliability (Win 1). Files: scripts/orca-dispatch.sh, scripts/orca-wait.sh, scripts/lib/orca-orch.sh, NEW tests/orca-wait.bats, NEW tests/orca-dispatch-launch.bats (both driven by a stub orca-ide/orca on PATH that replays canned JSON from fixture files and logs every argv to a file; the existing tests/orca-dispatch.bats uses the real xvfb CLI and is not part of this contract).
Behaviour:
1. The dispatch record (.claude-dev/run/orchestration/dispatch/<id>.json) gains started_at (epoch seconds) and worktree_path (the directory behind a path: selector, else empty).
2. orca-wait gains --stall-after <sec> (default 600) and --poll <sec> (default 60): it loops on 'orchestration check --wait' in poll-sized waits until the overall --timeout-ms, and between waits inspects every dispatch record in state ready/running. Activity for a record = the newest of: started_at, the time of the last heartbeat/question/escalation message seen from that dispatch (persist last_activity in the record when a message arrives), the HEAD commit time of worktree_path, and the newest mtime among files 'git -C worktree_path status --porcelain' lists. If now - activity > stall-after: print one receipt {"type":"stalled","bead","dispatch_id","terminal","idle_s","nudge":"orca terminal send --terminal <h> --text ... --enter"} and, unless --no-nudge, send exactly one nudge through 'orca terminal send' telling the worker to continue and to heartbeat, recording nudged_at in the record. If a record already has nudged_at and stalls again, print {"type":"stalled","nudged":true,"fallback":"<the Agent-tool spec, as orch_fallback prints it>","worktree_path":...} and return 0 so the orchestrator can re-run the slice in-process on the same worktree.
3. WORKER RULES (orch_spec in lib/orca-orch.sh) gain one rule: after every commit and at least every 5 minutes of work, send 'orca-ide orchestration send --type heartbeat --subject alive --task-id <t> --dispatch-id <d> --json'; and orca-wait treats a heartbeat as activity without printing a receipt for it beyond one stderr note.
4. orca-dispatch: --worktree new-child passes --name wt/<bead-id> to worker-start (and the worktree_path recorded is whatever worker-start's JSON reports). When worker-start reports state failed, read the terminal ('orca terminal read --terminal <h> --json'), store its last 8 non-empty lines as launch_tail in the record, print the receipt with reason=<last line> on STDERR, print the Agent-tool fallback spec (orch_fallback) on STDOUT and exit 3 -- the same contract the unreachable-runtime path already has -- so the orchestrator falls back at once instead of guessing.
5. Stagger: before worker-start, if the newest dispatch record was written less than CLAUDE_ORCA_DISPATCH_STAGGER_MS (default 5000) ago, sleep the remainder, so a fan-out wave shares the first worker's cached prefix and does not burst the per-minute rate limit.
bash 3.2 clean (scripts/ is scanned). Keep tests/orca-dispatch.bats green (run it once; it needs the xvfb CLI, if that is unavailable here say so and do not edit it).
DISPATCH RULES: write files in <=150-line Edit/Write pieces, one file per response; copy PASS-IF case names VERBATIM into @test lines, one @test per case; dry-run each assertion against a hand-built fixture before committing RED; report under 60 lines.

## Slice C (claude-orca-8a0.3)
Slice C -- orchestrator context diet (Win 3). Files: python/delegation-gate.py (or scripts/delegation-gate.sh, whichever holds the logic), NEW scripts/output-cap.sh, config/claude-settings.json, scripts/container/entrypoint.sh, tests/delegation-gate.bats, NEW tests/output-cap.bats, tests/container-entrypoint.bats.
Behaviour:
1. Delegation gate: in the main loop (agent_id unset) every Bash call counts toward the streak unless its command matches the small read-only exempt list that already exists (keep that list, do not grow it), and past DELEGATION_GATE_DENY_AT the gate DENIES a Bash call the same way it denies edits, with the denial text naming the exact spawn to use (scout for recon, executor via orca-dispatch or Agent for edits). Subagent calls stay skipped entirely. lane express keeps its current exemption.
2. scripts/output-cap.sh, a PreToolUse hook on Bash: main loop only; skipped when tool_input.run_in_background is true, when CLAUDE_ORCA_OUTPUT_CAP is 0, or when the command already ends in a pipe to head/tail/wc. Otherwise it rewrites tool_input.command through hookSpecificOutput.updatedInput (the tier-gate.sh precedent) into a wrapper that runs the original command with stdout+stderr into a file under ${CLAUDE_ORCA_OUTPUT_DIR:-${TMPDIR:-/tmp}/claude-orca-output/<session_id>}, prints the first CLAUDE_ORCA_OUTPUT_CAP bytes (default 6000), appends one line '[output capped at N bytes of M; full output: <path>]' only when it was cut, and exits with the original command's exit code. The wrapper must survive commands containing single quotes, heredocs and && chains: write the original command to a file and run it with 'bash <file>' rather than interpolating it.
3. config/claude-settings.json: register output-cap on PreToolUse matcher Bash AFTER the existing guards; add "subagentPromptCacheTtl": "1h" at top level.
4. scripts/container/entrypoint.sh (runs as root before the privilege drop): if /etc/claude-code/managed-settings.json is absent, write {"autoContinueAtUsageLimit": true} there (mode 644); if it exists without the key, merge the key in with jq; never overwrite other keys. Skip silently when not root (tests run unprivileged: honour a CLAUDE_ORCA_MANAGED_SETTINGS override path so the test can point it at a temp file).
bash 3.2 for scripts/*.sh (scripts/container/* is exempt). DISPATCH RULES: write files in <=150-line Edit/Write pieces, one file per response; copy PASS-IF case names VERBATIM into @test lines, one @test per case; dry-run each assertion before committing RED; the container-entrypoint suite must run under 'env -u CLAUDE_ORCA_GIT_NAME -u CLAUDE_ORCA_GIT_EMAIL'; report under 60 lines.
